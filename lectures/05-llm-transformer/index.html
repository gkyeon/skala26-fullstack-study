1. Intro: Software 3.0

소프트웨어 개발 방식의 진화 · Software 1.0/2.0/3.0 · LLM이라는 새로운 실행환경 · 한계와 시사점

💡
쉽게 말하면: 소프트웨어를 만드는 방식이 바뀌고 있어요. 예전에는 사람이 규칙을 코드로 직접 짰고(1.0), 그다음엔 데이터를 주고 모델을 학습시켰죠(2.0). 이제는 사람이 목표(자연어)만 정해주면 LLM이 스스로 사고하고 행동합니다(3.0). 이번 장은 이 흐름이 왜, 어떻게 일어났는지를 다룹니다.

1) 소프트웨어 개발 방식의 진화

  • Software 1.0 — 사람이 규칙을 코드로 직접 작성하는 전통적 프로그래밍 방식. 개발자가 if-else, 반복문 등 명시적 로직을 하나하나 작성한다.
  • Software 2.0 — 사람이 데이터를 주고 모델을 학습시키는 방식(Andrej Karpathy가 처음 제시한 개념). 신경망 가중치가 "코드"가 되는 방식이며, Task-specific AI(이미지 분류기, 번역기 등 특정 작업에 특화된 모델)를 만든다.
  • Transformer와 LLM의 등장 — 2017년 "Attention Is All You Need" 논문 발표. Foundation Model 시대의 개막 — 하나의 거대 모델이 다양한 Task를 처리. LLM의 대중화(ChatGPT 등장으로 일반 대중까지 확산).
  • Software 3.0 — 사람이 목표(역할)를 정의하면 모델이 스스로 사고하고 행동하는 방식. 자연어 프롬프트가 곧 "프로그램"이며, AI Agent가 스스로 프로그램(코드)을 생성하고 실행한다.
🧭 Program space 개념: Software 3.0의 표현력이 Software 1.0과 2.0을 포함하는 상위 집합이다 — 자연어로 원하는 모든 종류의 프로그램(명시적 로직이든 학습된 패턴이든)을 표현할 수 있다.

3) Software 3.0: 언어가 코드가 되는 순간

자연어가 새로운 프로그래밍 언어가 된다. "소프트웨어의 인터페이스는 API가 아니라 언어다" — 누구나 자연어로 원하는 동작을 지시할 수 있어 프로그래밍의 진입장벽이 낮아진다.

4) Software 3.0 시대에서의 LLM

LLM은 단순한 모델이 아니라 새로운 실행환경(runtime)이다. 추론엔진(reasoning engine) / 지식 인터페이스(knowledge interface) / 자연어 컴파일러(natural language compiler) / 에이전트의 두뇌 — 이 네 가지 역할을 동시에 수행한다.

🎯 "LLM은 도구가 아니라 함께 일하는 새로운 형태의 소프트웨어다"

NLP/AI 기술 발전 타임라인: ELIZA(1967, 최초의 챗봇) → LSTM(1997) → Stanford CoreNLP(2010) → Google Brain(2011) → Transformer Architecture(2017) → OpenAI GPT-3(2020)

5) Limitation of Software 3.0

  • Black Box — 왜 그런 결과가 나왔는지 설명하기 어렵다.
  • Bias — 웹에서 수집한 학습 데이터에 내재된 편향이 그대로 반영된다.
  • Hallucination — 그럴듯하지만 사실이 아닌 내용을 생성한다.
  • Non-deterministic — 같은 입력을 줘도 실행마다 다른 결과가 나올 수 있다(결정론적이지 않음).

6) Software 3.0을 향하여 — Benefit

  • 개발 속도가 비약적으로 향상된다.
  • AGI(Artificial General Intelligence)를 향한 교두보로 여겨진다.

2. NLP Technical Summary

단어 표현부터 Transformer 등장까지 · One-hot·BoW·TF-IDF · Word2Vec · RNN/LSTM/Seq2Seq · Attention · GPT

💡
쉽게 말하면: 컴퓨터는 글자를 그대로 이해하지 못해서 숫자(벡터)로 바꿔야 해요. 그 방법이 점점 발전해온 역사가 이 장이에요. 처음엔 단어를 "있다/없다"로만 표현했다가(One-hot), 문맥을 반영한 벡터(Word2Vec)로, 다시 문맥에 따라 벡터가 달라지는 방식(Contextual Embedding)으로 진화했고, 그 끝에 Transformer와 GPT가 있어요.

1) 언어 이해의 시작, NLP

Machine이 언어를 이해하려면 텍스트를 수치(벡터)로 변환해야 한다. Corpus(말뭉치)는 자연어 처리를 위해 수집된 대량의 텍스트 데이터이고, Vocabulary(어휘 집합)는 Corpus에 등장하는 고유한 단어들의 집합이다.

2) One-hot vector와 BoW

  • One-hot vector — 어휘 집합 크기만큼의 차원을 가지고, 해당 단어의 위치만 1이고 나머지는 0인 벡터로 단어를 표현하는 가장 기본적인 방식.
  • BoW(Bag of Words) — 문서를 단어들의 등장 횟수(빈도)로 표현하는 방식. 단어의 순서는 무시하고 "가방에 단어를 쏟아부은 것"처럼 취급한다.

3) N-gram과 TF-IDF

  • N-gram — 연속된 N개의 단어(또는 문자)를 하나의 단위로 취급하여 순서 정보를 어느 정도 반영하는 방법(예: bigram, trigram).
  • TF-IDF(Term Frequency-Inverse Document Frequency) — 특정 문서에서 단어가 얼마나 중요한지를 나타내는 지표. 문서 내 빈도(TF)가 높으면서 전체 문서군에서는 드물게 등장하는 단어(IDF)일수록 높은 가중치를 가진다.

4) 빈도기반 표현의 한계

  • 순서 정보를 반영하지 못함(BoW의 경우)
  • 차원의 저주(curse of dimensionality) — 어휘 집합이 커질수록 벡터 차원이 기하급수적으로 커지고 희소(sparse)해진다.
  • 의미적 관계를 표현하는 데 취약 — "사과"와 "오렌지"가 관련 있다는 것, "동생"과 "아우"가 유사한 의미라는 것을 빈도 기반 표현은 포착하지 못한다.

5) Thesaurus(WordNet)

단어 간의 관계(동의어, 상위어, 하위어 등)를 사람이 직접 구축한 그래프 형태의 사전. 한계: 신조어에 대응하기 어렵고(사람이 수작업으로 업데이트해야 함), 구축 비용이 매우 높다.

6) 맥락(Context) 이해 — 분포가설

분포가설(Distributional Hypothesis): 언어학자 Zellig Harris가 제시한 가설. 비슷한 맥락에서 등장하는 단어들은 비슷한 의미를 가진다는 개념이다.

🔎 "You shall know a word by the company it keeps"

J.R. Firth의 유명한 문구 — "단어는 함께 등장하는 이웃 단어들을 보면 그 의미를 알 수 있다"는 뜻이다.

7) Word Embedding(Word2Vec)

딥러닝으로 분포가설을 구현한 대표적 방법론이다. 학습 과정: 주변 단어(context)로부터 중심 단어를 예측하거나(CBOW), 중심 단어로부터 주변 단어를 예측(Skip-gram)하는 과정에서 단어의 의미가 벡터 공간에 학습된다.

King − Man + Woman ≈ Queen
Reasoning(추론) 능력 — 벡터 연산으로 단어 간 관계를 표현할 수 있다

Embedding Space 시각화: 학습된 Word Embedding을 2차원/3차원으로 축소해 시각화하면, 의미적으로 유사한 단어들이 벡터 공간에서 서로 가까운 위치에 군집을 이루는 것을 확인할 수 있다.

8) What is LM(Language Model)

다음 단어를 예측하는 모델 — 주어진 단어열(context) 다음에 어떤 단어가 올지 확률적으로 예측한다.

9) RNN(Recurrent Neural Network)

순차적으로 데이터를 처리하며, hidden state를 통해 이전 시점의 정보를 "기억"해 다음 시점 처리에 활용한다.

⚠️ 한계: Vanishing Gradient(기울기 소실) 문제 — 시퀀스가 길어질수록 초반 정보가 학습 과정에서 희미해진다.

10) LSTM/GRU와 Seq2Seq

  • LSTM(Long Short-Term Memory)/GRU(Gated Recurrent Unit) — Gate mechanism(입력 게이트, 망각 게이트, 출력 게이트 등)을 도입해 RNN의 장기 의존성 문제를 완화한다.
  • Seq2Seq(Sequence-to-Sequence) — Encoder-Decoder 구조. Encoder가 입력 시퀀스를 하나의 고정 크기 Context vector로 압축하고, Decoder가 이를 바탕으로 출력 시퀀스를 생성한다.

한계: Context vector로의 압축 과정에서 정보 손실이 발생한다(특히 긴 시퀀스일수록 심함).

11) Attention 매커니즘

Seq2Seq의 Context vector 병목 문제를 해결하기 위해 등장했다. Decoder가 매 출력 시점마다 Encoder의 hidden state 전체를 참고할 수 있게 함으로써, 장기 의존성 문제와 정보 압축 손실 문제를 동시에 완화한다. 이후 병렬처리의 한계까지 극복하는 방향으로 발전한다(→ Transformer).

12) Contextual Embedding

Word Embedding(Word2Vec 등)의 한계: 각 단어가 고정된 하나의 벡터만 가진다 → 동음이의어/다의어를 구분하지 못한다(예: "배"가 과일인지 신체부위인지 교통수단인지 구분 불가). Transformer 기반 모델(BERT, GPT 등)은 같은 단어라도 문맥에 따라 서로 다른 벡터(Contextual Embedding)를 생성 — 문맥을 반영한 진짜 의미 표현이 가능해진다.

13) Transfer Learning

Pretrained Model(대량의 범용 데이터로 미리 학습된 모델)을 가져와 특정 Task에 맞게 전이학습(Fine-tuning)하는 방식. 처음부터 학습하는 것보다 훨씬 적은 데이터와 자원으로 높은 성능을 달성할 수 있다.

14) 대규모 데이터와 Transformer의 만남, GPT

GPT(Generative Pretrained Transformer)의 등장 — Transformer 아키텍처와 대규모 데이터·컴퓨팅 자원이 만나 이전과 차원이 다른 언어모델 성능을 보여준다.

15) Scale up — GPT1 vs GPT2 vs GPT3

GPT1(2018) → GPT2(2019) → GPT3(2020)로 갈수록 모델 크기(파라미터 수)가 극적으로 증가했다.

3. Math Essentials for Transformer

Distance·Similarity · Euclidean Distance · Cosine Similarity · Dot Product · 행렬곱·선형변환 · Softmax

💡
쉽게 말하면: Transformer는 결국 벡터끼리 "얼마나 비슷한지"를 계산하는 기계예요. 이 장에서 배우는 코사인 유사도·내적·행렬곱·소프트맥스는 전부 다음 장의 Self-Attention 계산(Q·Kᵀ → Softmax → ·V)을 이해하기 위한 최소한의 도구입니다.

1) Distance(거리)와 Similarity(유사도)

두 벡터가 얼마나 가까운지(Distance) 또는 얼마나 비슷한지(Similarity)는 서로 반대 개념이다. 일반적으로 1 − Similarity = Distance 관계로 변환 가능하다(정규화된 유사도 기준).

2) Euclidean Distance(유클리드 거리)

두 점 사이의 직선 거리를 계산하는 가장 직관적인 거리 측정 방법. 피타고라스 정리에 기반한다.

d(A,B) = √( Σ (Aᵢ − Bᵢ)² )

3) Cosine Similarity(코사인 유사도)

두 벡터 사이의 각도를 기반으로 유사도를 측정 — 벡터의 크기(magnitude)는 무시하고 방향(direction)만 고려한다.

cos(θ) = (A·B) / (|A||B|)
방향이 완전히 같으면 1, 직각이면 0, 완전히 반대면 −1

텍스트 임베딩처럼 벡터의 크기보다 방향(의미)이 중요한 경우에 널리 사용된다.

4) Case Study — 문서 유사도 비교

문서1, 문서2, 문서3을 각각 단어 빈도 기반 벡터로 표현했을 때, Cosine Similarity를 계산해 어떤 문서 쌍이 의미적으로 더 유사한지 비교하는 예시. 벡터의 절대적 크기(문서 길이 차이)에 영향받지 않고 내용의 유사성만 비교할 수 있다는 것이 핵심 장점이다.

Cosine Similarity 계산 예시
A = [2, 0, 1]   # 문서1의 단어빈도 벡터
B = [1, 0, 3]   # 문서2의 단어빈도 벡터

dot(A,B)   = 2*1 + 0*0 + 1*3 = 5
|A|        = sqrt(2^2+0^2+1^2) = sqrt(5)
|B|        = sqrt(1^2+0^2+3^2) = sqrt(10)

cos(theta) = 5 / (sqrt(5)*sqrt(10)) = 5 / sqrt(50) ≈ 0.707

5) Dot Product(내적)

두 벡터의 각 성분을 곱해서 더한 값 — 크기(magnitude)와 방향(direction)을 모두 반영한다. Cosine Similarity와 달리 벡터의 크기에도 영향을 받는다.

🔑 Transformer의 Attention Score 계산(Q·Kᵀ)에 핵심적으로 사용되는 연산이 바로 이 Dot Product다.

6) Matrix Multiplication(행렬 곱)

여러 벡터 연산을 한번에 효율적으로 처리하기 위한 핵심 연산. Transformer의 모든 주요 계산(Q,K,V 생성, Attention Score 계산, Linear layer 등)이 행렬 곱으로 구현된다.

7) 선형변환(Linear Transformation)

벡터를 다른 벡터 공간으로 매핑하는 연산. Weight matrix(가중치 행렬)를 벡터에 곱함으로써 입력 벡터를 원하는 차원/공간의 다른 벡터로 변환한다. Transformer에서 Q, K, V를 생성할 때, 그리고 Feed Forward 층에서 핵심적으로 사용된다.

8) Softmax function

여러 개의 실수 점수(score)를 모두 더하면 1이 되는 확률 분포로 변환하는 함수.

softmax(xᵢ) = e^xᵢ / Σⱼ e^xⱼ

Attention Score를 확률적 가중치로 변환하거나, 최종 출력 토큰의 확률 분포를 계산할 때 사용된다.

4. Transformer

Attention Is All You Need · Scaled Dot-Product Attention · Multi-head Attention · Encoder-Decoder · Masked Self Attention

💡
쉽게 말하면: Transformer는 "각 단어가 문장 속 다른 모든 단어를 한 번에 훑어보고 얼마나 집중(attention)할지 계산"하는 구조예요. RNN처럼 순서대로 하나씩 읽지 않아도 되니 병렬 학습이 가능해졌고, 그 덕분에 지금의 모든 LLM(GPT, BERT 등)이 이 구조 위에서 만들어졌어요.

1) Attention Is All You Need 논문

2017년 Google Brain 팀이 발표한 논문(Vaswani et al.). 원래는 기계번역(Machine Translation) 문제를 풀기 위해 나온 논문이었다 — 처음부터 "범용 언어모델"을 노린 논문이 아니라, 당시 WMT(기계번역 학회) 컴페티션에서 경쟁하던 논문이었다는 점이 배경을 이해하는 데 중요하다.

  • Motivation — 기존 RNN/LSTM/GRU는 순차 처리 특성상 병렬화가 어렵고 학습이 느리다. 또한 시퀀스가 길어질수록 장기 의존성(long-term dependency) 문제가 발생한다. CNN 기반 접근은 먼 거리의 관계를 포착하려면 매우 깊은 계층이 필요하다.
  • 당시 경쟁 구도 — WMT 컴페티션의 주류는 크게 두 계열이었다: ① RNN/LSTM/GRU 등 시계열 모델 계열(Seq2Seq 포함), ② CNN(이미지 모델)을 언어에 응용한 계열(비전이 상하좌우를 보듯, 위아래를 잘라 좌우만 보게 응용). Transformer는 이 두 계열을 모두 제치고 SOTA를 달성했다.
  • Proposal — RNN이나 CNN 없이, Self-Attention 메커니즘만으로 시퀀스 전체를 처리하는 새로운 아키텍처를 제안한다.

3) Contribution

  • RNN/CNN 없이 Self-Attention만으로 작동하는 최초의 Seq2Seq 아키텍처.
  • 순차 처리가 필요 없어 병렬 학습이 가능해지면서 학습 속도가 비약적으로 향상됨.
  • 동시에 장기 의존성 문제도 자연스럽게 해결(모든 토큰이 서로 직접적으로 attention 가능).
  • 이후 BERT, GPT 등 현재의 모든 주요 LLM이 이 Transformer 아키텍처를 기반으로 함 — 실제로 GPT의 "T", BERT의 "T"가 모두 이 Transformer에서 따온 이름이다.

4) Transformer Architecture

전체적으로 인코더(Encoder)-디코더(Decoder) 구조로 구성된다. 인코딩(Encoding)은 자연어처럼 비정형인 정보를 벡터로 만드는 것, 디코딩(Decoding)은 반대로 벡터로 되어 있는 것에서 다시 자연어 문장을 생성하는 것을 말한다.

✔ Encoder → Decoder 큰 흐름
  • Encoder: 입력 시퀀스 → 문맥이 반영된 표현(representation) 생성
  • Decoder: Encoder의 출력 + 지금까지 생성된 토큰들을 참고 → 다음 토큰을 순차적으로 생성
🔑 위 구조도에서 Feed Forward, Add&Norm 같은 레이어 대부분은 원래 존재하던 기술이고, 오직 "Multi-Head Attention" 박스만 이 논문에서 새롭게 제시된 핵심 아이디어다.

5) Transformer Encoder — Scaled Dot-Product Attention

Q(Query), K(Key), V(Value) 개념: 각 입력 토큰의 임베딩에 서로 다른 Weight Matrix를 곱해 만들어지는 세 가지 벡터.

구성역할
Query"내가 지금 무엇을 찾고 있는가"
Key"나는 어떤 정보를 갖고 있는가"(다른 토큰들이 검색할 수 있는 색인 역할)
Value"실제로 담고 있는 내용물"
🔎 Q, K, V는 사람이 붙인 사후적 해석일 뿐, 모델이 이 의미를 "이해"하고 학습하는 것은 아니다 — 학습을 마친 뒤 연산 결과를 보고 사람이 붙인 이름표에 가깝다.

5-1) 왜 Cosine Similarity가 아니라 내적(Dot Product)을 쓰는가

내적을 기하학적으로 보면, 한 벡터를 다른 벡터 위로 정사영(projection)시킨 길이 × 다른 벡터의 크기다. 태양이 바로 위에서 내리쬘 때 생기는 "그림자의 길이"를 떠올리면 된다 — 두 벡터가 완전히 겹치면(0°) 그림자가 가장 길어 내적값이 최대, 각도가 벌어질수록 그림자가 짧아져 내적값도 작아지고, 90°가 되면 그림자가 사라져(cos90°=0) 내적값도 0이 된다. 즉 내적은 그 자체로 "닮음의 정도"를 나타내는 숫자다.

🔑 다만 Cosine Similarity는 계산할 때 두 벡터의 크기(노름)를 구해서 나눠주는 연산이 추가로 필요해 어휘가 수십만 개인 경우 비용이 크다. 반면 내적 → 스케일링(√d_k로 나누기) → Softmax 조합은 훨씬 연산 효율적이면서도 비슷한 정규화 효과(값이 크면 주목도↑, 0에 가까우면 주목도↓)를 낸다 — 그래서 Attention Score 계산에는 Cosine Similarity 대신 내적을 사용한다.
Scaled Dot-Product Attention — 계산 흐름
Q, K, V = X·Wq, X·Wk, X·Wv        # 입력 임베딩 X에 가중치 행렬을 곱해 생성

Score = Q · K^T                   # (1) 내적으로 토큰 쌍 사이의 연관성 점수 산출
Scaled = Score / sqrt(d_k)        # (2) Key 차원 수의 제곱근으로 나눠 스케일 조정
Weights = softmax(Scaled)         # (3) 확률분포(주목도 가중치)로 변환
Output = Weights · V              # (4) 가중치를 Value에 곱해 최종 Attention 출력(가중합)
  • Score Matrix 계산 — Q와 K를 내적(Q·Kᵀ)해 각 토큰 쌍 사이의 연관성 점수(Score)를 산출한다.
  • Scaling — 계산된 Score를 K 벡터 차원 수의 제곱근(√d_k)으로 나누어 스케일 조정한다(값이 너무 커져서 softmax의 기울기가 소실되는 것을 방지).
  • Softmax — 스케일링된 Score에 softmax를 적용해 확률 분포(각 토큰에 대한 주목도 가중치)로 변환한다.
  • Attention Output — 이 확률 분포(가중치)를 V(Value)에 곱해서 최종 Attention 출력(가중합)을 생성한다.
Attention(Q,K,V) = softmax( QKᵀ / √d_k ) · V

5-2) 단계별 숫자로 따라가 보기 (Single Head 기준)

전제: 입력 문장 "I study AI hard"(4개 단어), 각 단어는 Word Embedding으로 10차원 벡터라고 하면, 입력 행렬 X는 (4×10) 크기다.

Scaled Dot-Product Attention — 4단어 예시로 차원 따라가기
[Step 1] Q, K, V 생성
  X(4x10) 에 서로 다른 가중치행렬 Wq, Wk, Wv (각 10x5) 를 각각 곱함
  → Q(4x5), K(4x5), V(4x5)   # 10차원 → 5차원으로 선형 변환(차원 축소)

[Step 2] Score = Q · K^T
  Q(4x5) x K^T(5x4) = Score(4x4)
  → Score[i][j] = i번째 토큰의 Q벡터와 j번째 토큰의 K벡터의 내적
  → "자주 함께 등장/맥락적으로 유사한 쌍일수록 값이 크다"

[Step 3] Scaling: Score / sqrt(d_k)     # d_k=5 이므로 sqrt(5)로 나눔
  → 차원이 커질수록 내적값의 분산이 커져 softmax 그래디언트가
    소실되는 것을 막기 위한 정규화

[Step 4] Softmax (행 단위로 적용)
  → Score(4x4)의 각 "행"마다 softmax를 적용, 행의 합이 정확히 1이 되게 함
  → 예: "I" 행 = [I를 40%, study를 30%, AI를 20%, hard를 10% 주목]

[Step 5] Output = Weights(4x4) x V(4x5) = Output(4x5)
  → 주목 비중(가중치)만큼 V를 섞어 재표현
  → "I"의 출력 = 0.4*V(I) + 0.3*V(study) + 0.2*V(AI) + 0.1*V(hard)

6) Multi-head Attention

하나의 Attention만 쓰는 게 아니라, 여러 개(head)의 서로 다른 Q,K,V Weight Matrix를 병렬로 두어 각기 다른 관점(문법적 관계, 의미적 관계 등)에서 동시에 주목(attention)하게 한다. 각 head의 출력을 Concat(이어붙임)한 뒤 하나의 Linear layer를 통과시켜 최종 출력을 생성한다.

🔑 왜 여러 head가 필요할까 — 하나의 Attention head는 "한 가지 관점"만 학습하기 쉽다. 여러 head를 두면 어떤 head는 문법적 관계(주어-동사)를, 어떤 head는 의미적 관계(단어의 지칭 대상)를 각각 포착할 수 있다(이 역시 사람이 지시한 게 아니라 학습 후 사후적으로 관찰되는 경향).
  • 차원 분할 — 전체 임베딩 차원을 head 개수로 미리 나눠서 계산한다. 예를 들어 원래 차원이 8개 head로 나뉘면, 각 head는 "전체차원 ÷ 8" 크기로 Q,K,V를 만든다 → 이렇게 해야 나중에 이어 붙였을 때 원래 차원으로 복원된다.
  • Concatenate(연결) — 각 head의 결과를 옆으로 그냥 이어붙여 원래 차원으로 복원한다.
  • Linear Layer 추가 — Concat 직후에는 서로 다른 head의 결과가 "이질적으로" 붙어있는 상태이므로, 가중치 행렬을 한 번 더 곱해 정보를 섞어(재조합) 다음 레이어가 쓰기 좋은 하나의 통합된 표현으로 만들어준다.

7) Encoder Process

  • LayerNorm(Layer Normalization) — 복잡한 연산을 거치며 값의 분포가 뒤틀릴 수 있는데, 학습 안정성과 속도를 위해 각 층을 지날 때마다 분포를 다시 정돈해주는 작업이다.
  • Residual Connection(잔차 연결) — 원래 비전(CNN) 모델에서 가져온 아이디어. 레이어를 여러 번 거치며 추상화가 심해지면 원래 입력의 정보가 아예 사라질 수 있어, 원래 입력값을 연산 결과에 다시 더해줌으로써(skip connection) 원본 정보를 보존하고 깊은 네트워크에서도 기울기가 잘 전달되도록 한다. 공식으로 쓰면 Output = LayerNorm(Input + MultiHeadAttention(Input)).
  • Feed Forward — Attention 연산까지는 대부분 선형 변환(Linear)의 조합이라 표현력에 한계가 있다. 완전연결층(FC layer)과 ReLU 등 비선형 활성화 함수를 추가로 거쳐, 선형 변환만으로는 할 수 없는 표현을 가능하게 한다.
  • Positional Encoding — Attention은 모든 토큰을 "동시에" 참고하는 방식이라 순서 정보를 자체적으로 알 수 없다("나는 밥을 먹었다"와 "밥이 나를 먹었다"를 구분 못함). 그런데 시퀀스 길이가 문장마다 다르기 때문에 단순히 1,2,3,4...를 더할 수는 없다 — 그래서 -1~1 범위 안에서 위치마다 서로 다른 규칙적인 값을 만들어내는 삼각함수(sin, cos) 기반 벡터를 입력 임베딩에 더해줌으로써 순서 정보를 보완한다(같은 단어라도 문장 속 몇 번째 자리인지에 따라 최종적으로 더해지는 벡터가 달라진다). 원 논문은 학습이 필요 없는 고정된 계산식을 쓰지만, 학습 가능한 위치 임베딩 레이어를 쓰는 방식도 있다.

Encoder Layer 하나의 흐름: Input Embedding + Positional Encoding → Multi-Head Attention → Add & Norm → Feed Forward → Add & Norm — 이 블록을 N번 반복한다.

8) Transformer Decoder

  • Masked Self Attention — 인코더의 Attention은 문장의 모든 단어가 이미 주어진 상태에서 서로의 문맥을 파악하므로 "미래 토큰까지 전부 참고 가능"하다. 하지만 실제 생성(디코딩) 시점에는 아직 만들어지지 않은 미래 토큰을 미리 볼 수 없으므로, 학습 때도 이 조건을 강제로 맞춰줘야 한다. 방법은 Attention Score를 평소처럼 다 계산한 뒤, 대각선 위쪽(미래에 해당하는 부분)의 값을 극단적으로 큰 음수(−∞에 가까운 값)로 바꿔치기하는 것 — 이후 Softmax를 거치면 e^(−∞) ≈ 0이 되는 성질(5.7절 참고) 덕분에 그 값들이 자동으로 0이 되어 "미래는 안 보이게" 처리된다. 예를 들어 "I"가 입력될 때는 "I"까지만, "study"가 입력될 때는 "I study"까지만 보고 다음 토큰을 예측하는 구조가 만들어진다.
  • Learning — 모델이 예측한 다음 토큰 확률 분포와 실제 정답 토큰 사이의 차이를 Loss(주로 Cross-Entropy Loss)로 계산하고, 이를 역전파(Backpropagation)해 전체 가중치(Q,K,V Weight Matrix 포함)를 업데이트하며 학습한다.
✔ Encoder vs Decoder Self-Attention 차이
  • Encoder Self-Attention — 모든 토큰이 서로(앞·뒤 모두) 자유롭게 attention 가능
  • Decoder Masked Self-Attention — 각 토큰은 자기 자신과 그 이전 토큰까지만 attention 가능(미래 마스킹)

9) 전체 흐름 한눈에 정리

✔ 입력 단어 → 다음 토큰 예측까지 9단계
  • ① 입력 단어 → Word Embedding(+Positional Encoding)으로 벡터화
  • ② Q, K, V 세 벡터 생성(선형 변환)
  • ③ Q·Kᵀ 내적 → Attention Score(원시) 생성 = "누가 누구를 얼마나 주목하는가"의 초벌 점수
  • ④ √d_k로 나눠 스케일링(값이 너무 커지는 것 방지)
  • ⑤ 행(토큰)별로 Softmax → 확률로 정규화된 진짜 Attention Score
  • ⑥ Attention Score × V → 문맥이 반영된 새로운 벡터(재표현) 획득
  • ⑦ (Multi-Head라면) 여러 head의 결과를 Concat + Linear로 재조합
  • ⑧ Add & Norm(잔차연결+정규화) → Feed Forward(비선형성 추가) → Add & Norm
  • ⑨ (디코더의 경우) 위 과정에 마스킹을 추가해 "현재까지만 보이게" 만든 뒤 다음 토큰 확률을 Softmax로 산출

현업 문제 발굴 → AI Agent 구축 → 자동화 → 성과 측정

앞으로 3~5년은 AI Engineer ∩ Consultant ∩ Data Analyst의 교집합에 있는 사람(엔지니어링 감각 + 제품 감각 + 비즈니스 감각)이 가장 높은 가치를 받을 가능성이 높다.

  • 사전 학습(Pre-training) — 대량의 텍스트 데이터로 사전 학습해 문법·의미·문맥을 파악하고, 이후 특정 작업에 맞게 미세 조정(Fine-tuning)한다.
  • 자연어 처리 작업 수행 — 문장 생성, 번역, 요약, 감정 분석, 질문 답변 등 다양한 NLP 작업을 수행한다.
  • Transformer 아키텍처 — 문맥을 이해하고 병렬적으로 데이터를 처리할 수 있는 능력이 LLM의 핵심 기술적 특징이다.

7. Modern LLM Technologies

RLHF · Scaling Law · Chinchilla's Scaling Law · DeepSeek · Distillation · MoE(Mixture of Experts)

💡
쉽게 말하면: 이 장은 요즘 LLM을 실제로 "더 똑똑하고, 더 싸게, 더 사람 취향에 맞게" 만드는 4가지 핵심 기술이에요. RLHF는 사람 취향을 가르치고, Scaling Law는 얼마나 키워야 똑똑해지는지 알려주고, Distillation은 큰 모델의 지식을 작은 모델에 옮기고, MoE는 필요한 부분만 계산해서 효율을 높여요.

1) RLHF — 사람의 선호(취향)를 담아보자

Reinforcement Learning from Human Feedback. 사람의 선호(Feedback)를 이용하여 LLM이 더 도움이 되고, 더 안전하며, 사람의 의도에 맞게 답변하도록 학습하는 기법이다.

Why? 대규모 사전학습(Pretraining)만 한 LLM은 지식은 뛰어나지만, 다음 단어를 잘 예측하도록 학습되었을 뿐 사람이 좋아하는 답변을 배우지는 않는다. 무례하거나 질문 의도를 빗나간 답, 공격적·장황한 답변이 나올 수 있어 '정답을 맞히는 모델'에서 '친근한 표현으로 사람을 만족시키는 모델'로 진화할 필요가 생겼다.

RLHF 정렬 전/후 응답 비교
Q) 파이썬에서 리스트를 뒤집는 방법을 알려줘.

[일반 응답]
reverse()를 사용하면 됩니다.

[RLHF 정렬된 응답]
리스트를 뒤집는 방법은 두 가지가 있습니다.
1. reverse() -> 원본 리스트를 변경
2. a[::-1]   -> 새로운 리스트를 생성
상황에 따라 적절한 방법을 선택하면 됩니다.

대부분의 사람은 더 친절하고 설명이 풍부하며 실용적인 답변을 선호한다. RLHF는 '정답을 맞히는 능력'이 아니라, '사람이 더 선호하는 답변을 생성하는 능력'을 학습하는 과정이다.

RLHF Workflow

① Supervised Fine-Tuning(모범답변 지도학습) → ② Reward Model(선호도 점수화) → ③ Reinforcement Learning(보상 최대화 학습, PPO)
③ 세부 순환: 현재 정책(LLM) → 답변 생성 → Reward Model(보상 예측) → 보상 점수 → 정책 업데이트 → 다시 현재 정책으로
구분내용
Benefit지시 이해력 향상, 응답의 정중함·일관성 향상 → 사람 같은 답변. ChatGPT 등 생성형 AI의 대화 품질은 RLHF에 의해 유도됨
LimitationReward Hacking(무난하고 안전한 답변만 학습해 다양성 감소), 사람마다 선호가 달라 편향 발생, Human Labeling 비용이 큼

2) Scaling Law — 모델이 커질수록 LLM은 더 똑똑해질까?

"우리는 우리에게 새로운 아이디어가 필요하다고 생각했지만, 규모를 키우는 것만으로도 우리가 원하는 바를 구현할 수 있었다." — GPT-3 Developer, Jared Kaplan, 2021 NeurIPS 공개 토론회

Concept: 모델 크기(Parameter), 학습 데이터(Data), 연산량(Compute)을 증가시키면 LLM의 성능이 예측 가능한 방식으로 향상된다는 경험적 법칙. Loss는 세 요소가 증가할수록 Power Law 형태로 감소한다.

Loss ∝ N^(−α)  (Parameter)  ·  Loss ∝ D^(−β)  (Data)  ·  Loss ∝ C^(−γ)  (Compute)
로그-로그 그래프에서 거의 완벽한 직선(Power Law) 형태로 나타남
🔀 Scaling Law가 바꾼 AI 개발: 과거 "더 좋은 모델 구조를 만들자"(알고리즘 경쟁) → Scaling Law 이후 "더 크게 학습시키자"(인프라 경쟁). GPT가 발전해오는 동안 Transformer 구조 자체는 크게 변하지 않았다 — 대신 더 큰 모델, 더 많은 데이터, 더 많은 GPU를 사용했다.

3) Chinchilla's Scaling Law — 반전

무조건 크게 만들면 될까? 2022년 Google DeepMind가 발표한 Chinchilla는 "큰 모델 + 적은 데이터"보다 "적절한 모델 크기 + 충분한 데이터"가 더 나은 성능을 보임을 관찰했다. Scaling에도 최적 비율이 존재한다.

5) Distillation — 좋은 모델로 작은 모델을 만들 수 없을까?

SOTA 수준의 모델을 모든 회사가 학습시킬 수 있을까? 수천~수만 개 GPU, 수개월 학습, 막대한 비용이 필요해 거의 불가능하다. DeepSeek는 R1이 생성한 추론(Reasoning) 데이터를 이용해 작은 모델들을 증류(Distillation)했다.

DeepSeek-R1(Teacher, High Capability·High Cost) → Reasoning Data(CoT/Solutions/Explanations) 전달 → Distilled Student Models(1.5B / 7B / 8B / 14B / 32B)

Concept: 큰 모델이 Reasoning을 통해 답변을 생성하면 Student 모델은 그 추론(사고) 과정까지 함께 학습한다 — 정답만 학습하는 것이 아니라 생각하는 방법까지 학습한다. Distillation은 모델을 압축하는 것이 아니라 Teacher 모델의 능력을 Student 모델에게 전달하는 과정이다.

Hard Label vs Soft Label

구분형식예시(고양이 이미지)정보량

✔ Knowledge Distillation에서 Soft Label의 역할
  • 일반화 성능 향상 — Teacher Model의 학습 경험(클래스 간 유사성 정보)을 포함해 Student가 Hard Label보다 더 일반화된 성능을 갖춤
  • 학습 안정화 — 더 꼼꼼하게 학습을 진행할 수 있어 과적합을 줄이는 데 효과적
  • 추론 속도 향상 — 안정적으로 학습된 Student Model은 실시간 적용 환경에서도 빠르게 대응 가능

6) MoE(Mixture of Experts) — 필요한 전문가만 활성화한다

"모든 파라미터를 항상 사용할 필요가 있을까?"

구분Dense TransformerMoE(Mixture of Experts)
파라미터 활성화모든 뉴런/파라미터가 매 토큰마다 사용됨(All experts always active)Router가 선택한 일부 Expert만 활성화(Only a few experts activated per token)
연산 효율낮음 — 항상 전체 연산높음 — 대부분 파라미터는 비활성 상태로 연산 절감
흐름Question → Transformer Layer(전체) → OutputQuestion → Router → 일부 Expert만 선택·활성화 → Combine(가중합) → Output

Mixtral의 MoE Layer 예시: 각 입력 벡터는 라우터(router)에 의해 8개 Expert 중 2개에 할당되고, 레이어의 출력은 선택된 두 Expert 출력의 가중합이다. Expert는 일반 Transformer의 표준 feedforward 블록과 동일한 구조를 갖는다.

Router Workflow

Score = xWᵣ → Softmax: Pᵢ = e^sᵢ / Σⱼ e^sⱼ → Top-n Expert 활성화
Router도 작은 신경망(Linear Layer)이며 학습 대상이다

Expert는 어떻게 전문화될까? 처음에는 모두 동일하지만, 학습이 진행되면 Router가 비슷한 입력 토큰은 같은 Expert에게 계속 보내고, 해당 분야를 반복 학습하면서 전문화된 Expert가 된다.

🔧 MoE는 기존 Transformer의 Feed Forward 층을 MoE layer로 대체하는 방식으로 결합된다: Positional Encoding + Input Embedding → Multi-Head Attention → Add & Norm → Feed Forward(MoE layer로 대체 가능) → Add & Norm, 이 블록을 N번 반복.
